## 1. 目标、边界与兼容承诺

本规格只定义 rc8 的实现要求，不代表这些要求已经在基线代码中完成。实现工作由其他 AI agent 承担；规划与审核方只维护本文件和配套审核报告。

### 1.1 目标

rc8 必须同时完成两件事：

1. 将现有以文本匹配和隐式顺序为主的 17 规则冲突消解器，升级为“目录语义优先、自由文本回退、决策全程可追溯、最终不变量闭环”的确定性引擎。
2. 将硬编码在 `lib/sampler.py` 的单情境亲和池升级为带 Schema 的 14 情境 × 14 槽位多信号加权矩阵，并让真实采样到的场景与主题共同参与上下文计算。

### 1.2 不变的公开契约

以下契约在 rc8 中不得破坏：

- `IYKYKPromptGenerator`、`IYKYKPresetBrowser`、`IYKYKCustomSlotCombiner` 三个既有节点的类名、输入名称、输入类型、默认值、输出数量、输出顺序和返回类型全部不变。
- 17 个规则 ID 全部保留，且继续作为规则唯一稳定标识。
- 14 个情境 ID 全部保留：`school`、`office`、`medical`、`onsen_bath`、`bondage_sm`、`traditional`、`nightlife`、`domestic`、`transit`、`outdoor`、`dining`、`adult`、`special`、`generic`。
- `prompt_seed=-1` 继续表示每次生成新的实际 seed；非负 seed 在同一 rc8 代码与数据版本内必须逐字节复现相同输出和相同审计 JSON。
- rc7 与 rc8 使用同一 seed 时允许产生不同提示词；不得承诺跨版本随机序列兼容。
- ANGLE、QUOTED 以及包含黑盒后代的受保护结构继续保持字节不可改写、不可删除。完全不透明的 ANGLE/QUOTED 内容不进入语义正确率统计。

### 1.3 本轮不做的事项

- 不执行 Krea 2 Turbo 或任何其他模型的真实成图、主观评分或盲评。
- 不以图像观感替代结构化语义、提示词结果、统计分布和工程门禁。
- 不在本轮解决 Minerva 已记录的内容安全与上游授权问题；它们仍是整体发布的独立门禁。
- 不借 rc8 改名、删除或重排既有节点端口。

## 2. 基线事实与已知缺口

基线事实必须作为迁移前快照保留，不得在交付说明中被改写成 rc8 成果：

- 当前仓库为干净的 `main@fe88185`。
- 基线 169 项测试通过；严格校验覆盖 19 份运行时 JSON；规则 Schema 无漂移。
- `data/conflict_rules.json` 有 17 个规则、577 个 `PatternSpec`。
- `data/scenes.json` 有 122 个场景，但没有 `special` 场景；每个现有场景只有一个 `context_id`。
- `data/themes.json` 有 39 个主题，缺少稳定 ID 和 `context_ids`。
- `data/presets.json` 有 77 个预设，主体仍是扁平 `positive` 字符串；`data/style_recipes.json` 有 8 个扁平配方。
- 亲和矩阵和 `0.85` 常量硬编码在 `lib/sampler.py`，只覆盖现有八类槽位，且多个采样函数重复实现概率分支。
- 普通生成在场景为 `generic` 时使用原始 UI 字符串再次推断情境；随机主题的实际采样结果没有参与推断。
- 多数目录规则仍靠文本模式命中；现有目录没有形成手部占用、道具用途、昼夜、妆容状态等统一结构化事实。
- `rules_applied` 只能说明规则是否改变文本，不能回答删除、替换、注入的对象、原因、胜者和父来源。
- 当前 24 Atom 本机基准 p95 约为 `15.83 ms`；文本模式预编译的只读实验显示优化到 5 ms 附近具有可行性，但这不是当前正式实现成绩。

## 3. rc8 目标架构

```mermaid
flowchart LR
    A[四类入口\n普通生成/预设/配方/自定义] --> B[SelectionOrigin]
    B --> C[带稳定 ID 的目录选择]
    C --> D[SemanticFacts + PromptAtom]
    C --> E[真实 scene/theme 结果]
    E --> F[ContextProfile]
    F --> G[14×14 Affinity Sampler]
    G --> D
    D --> H[一次性语义索引]
    H --> I[规则 DAG]
    I --> J[最终硬冲突只读检测]
    J -->|0 个残余| K[ResolutionReport]
    J -->|可检测但受保护| L[UnresolvedConflictError]
    K --> M[既有三节点输出]
    K --> N[IYKYKPromptDiagnostics JSON]
```

实现必须保证：所有正式目录路径使用结构化事实；只有用户自由文本以及为旧数据兼容而显式标记的文本才进入 fallback。预设和配方不得继续通过扁平字符串绕过语义层。

## 4. 不可变类型与数据契约

### 4.2 `SelectionOrigin`

新增冻结类型 `SelectionOrigin`：

```text
entry_point: generator | preset_browser | custom_combiner | diagnostics
mode: none | random | auto | explicit | preset | recipe | custom | resolver
selector: 规范槽位名或 preset/recipe 字段名
selected_id: 稳定目录 ID，可空
raw_value: 原始 UI/自由文本值，可空
parent_ids: 有序父来源 ID 元组
```

`SelectionOrigin` 不替代现有 `TagProvenance`，而是补足“从哪个入口、以何种选择模式产生”的信息。`TagProvenance.parent_ids` 仍负责 Atom 级谱系。

### 4.3 `ContextProfile`

新增冻结类型 `ContextProfile`，至少包含：

```text
schema_version = "1.0"
weights = ((context_id, normalized_weight), ...)
scene_item_id
theme_id
scene_context_ids
theme_context_ids
```

`weights` 按 14 情境在配置中的固定顺序序列化；只保留正权重项，权重和必须在浮点容差 `1e-12` 内等于 1。

### 4.4 `ResolutionDecision` 与 `ResolutionReport`

每一次原子级变更必须生成一条冻结的 `ResolutionDecision`：

```text
decision_id          # sha256 规则生成的稳定 ID
sequence             # 从 0 开始的全局决策序号
rule_id
phase
action               # drop | replace | inject
reason_code           # 规则契约内声明的稳定枚举
winner_atom_ids       # 可为空；有多个胜者时保持全局 Tag 顺序
target_atom_id        # 被删/被替换原子；注入时为空
produced_atom_ids     # replace/inject 产生的新原子
before_text           # drop/replace 必填
after_text            # replace/inject 必填；drop 为空
parent_source_ids     # 必须最终闭环到 source_atoms
```

`ResolutionReport` 至少包含：

```text
schema_version = "1.0"
input_atom_hash
output_atom_hash
rules_applied
decisions
unresolved_conflicts
input_count
output_count
dropped_count
replaced_count
injected_count
```

`GenerationResult` 追加带默认值的 `effective_seed`、`context_profile`、`selections` 和 `resolution_report`。旧调用方只读取原字段时行为不变。

### 4.5 Atom 身份与谱系

- 输入 Atom ID 由“入口、源条目 ID、叶子 ID、全局 Tag 顺序、span 顺序”生成，不得使用进程地址或 Python `hash()`。
- 替换不得沿用旧 Atom ID。新 ID 固定为 `sha256("replace\0" + rule_id + "\0" + old_atom_id + "\0" + decision_ordinal)` 的前 24 个十六进制字符，并以 `atom_` 为前缀。
- 注入 ID 使用同样算法，前缀输入改为 `inject`，父 ID 按 Tag 顺序拼接。
- `source_atoms` 保存原始源原子；另建不可变 ledger 保存生成原子。每条 decision 的 `parent_source_ids` 必须递归落到 `source_atoms`，不得出现悬空、环或一对多歧义。

## 5. 数据迁移规范

- 保留已有稳定 ID，不因显示名、Tag 文案修正而改变。

### 5.5 预设和配方去旁路

每个预设继续保留 `positive`，同时新增 `fragments`。每个 fragment 至少包含 `id`、`slot`、`text`、`facts`、`origin`。严格校验：

```text
split_top_level_tags(positive)
== [fragment.text for fragment in fragments]
```

比较必须逐 Tag、逐顺序、逐字节相等，不做大小写折叠、空白修复或同义替换。`positive` 是兼容展示字段，运行时只消费 `fragments`。

8 个风格配方采用同一原则：保留原有扁平字段，同时为每个字段提供结构化 fragments；每个旧字段拆分后的 Tag 必须与其 fragments 逐项等价。配方 fragment 的 `source_slot` 必须规范化到 `lighting`、`pose`、`expression`、`makeup`、`film`、`quality` 或 `style_recipe`，不得继续使用 `recipe_lighting_palette` 等伪槽位绕过规则作用域。

自由文本入口先由现有顶层 Tag 解析器分片，产生 `mode=custom` 的 `SelectionOrigin`，再进入 `custom_text_only` fallback；它不能伪造正式目录 ID 或结构化事实。

### 6.2 上下文合并算法

设实际采样场景携带的情境集合为 `S`，实际采样主题携带的情境集合为 `T`：

```text
raw(c) = 1[c ∈ S] × 1.0 / |S| + 1[c ∈ T] × 0.6 / |T|
alpha(c) = raw(c) / Σ raw(k)
```

- 重复情境的质量相加后再归一化。
- 只允许消费 `scene_res.context_ids` 和 `theme_res.context_ids`，禁止消费原始 UI 显示文字。
- 如果 `S` 和 `T` 都为空，结果必须显式为 `generic=1.0`。
- `generic` 如果由实际场景或主题明确提供，就是普通信号，不因存在其他情境而偷偷丢弃。

### 6.3 概率公式

对槽位 `s`：

- `E_s`：当前已知硬约束下的合法选择器集合。
- `G_s`：`E_s` 上的全局合法分布；rc8 默认均匀，除非该 catalog 自身已声明基础权重。
- `C(c,s)`：矩阵候选与 `E_s` 交集后按候选权重归一化的分布。
- 当单元为 `neutral` 时，定义 `C(c,s)=G_s`，而不是缺字段回退。

最终分布固定为：

```text
P_s = 0.15 × G_s + 0.85 × Σ_c(alpha(c) × C(c,s))
```

要求：

- 用一个归一化 categorical draw 直接从 `P_s` 抽样；不能在 14 个采样函数中各写一套 Bernoulli 分支。
- `weighted` 单元与 `E_s` 的交集为空时抛出 `AffinityConfigurationError`，不得静默改用全局池。
- 只对 `Random` 和 `Auto` 使用本公式。`None` 保持空；显式选择保持该 ID，但之后必须进入强制冲突消解。
- 裸露、画质和真实微瑕不加入矩阵，保持情境中性。

### 6.5 独立 RNG 子流

不得使用 Python `hash()`。统一派生函数：

```text
material = "iykyk-rc8\0" + decimal(effective_seed) + "\0" + namespace
derived_seed = int.from_bytes(SHA256(material).digest()[0:16], "big")
```

固定命名空间：

- 选择器：`selector:scene_theme`、`selector:theme`、`selector:<canonical_slot>`。
- 亲和抽样仍使用对应 `selector:<slot>` 子流，不另取共享全局 RNG。
- 规则：`rule:<stable_rule_id>`。
- 裁剪或其他确需随机的后处理：`postprocess:<stable_operation_id>`。

一个槽位内部可以顺序消费自己的子流；其他槽位或规则的增删、重排不得改变该子流。诊断节点和主生成器必须调用同一生成函数，不能各自派生 seed。

### 7.2 一次性索引

每次 `resolve` 开始时只扫描输入 Atom 一次，构建不可变索引：

- `by_slot`
- `by_item_id`
- `by_origin_mode`
- `by_fact_name_and_value`
- `by_mutex_group`
- `by_parent_source_id`
- `ordered_detectable_atoms`

规则变更通过 ledger/tombstone 视图更新索引，不得让 17 个处理器反复全表扫描 577 个模式。文本 fallback 的正则对象必须在 `RuleRegistry` 加载时编译；运行时不允许调用 `re.compile()`。

### 7.3 权威关系与显式输入

固定权威关系：

| 冲突域 | 胜者 | 败者 |
| --- | --- | --- |
| 空间 | 场景 anchor | 环境 detail |
| 裸露/覆盖 | 裸露等级 | 服装覆盖/穿着描述 |
| 服装结构 | 服装拓扑 | 穿脱动作 |
| 视线几何 | 镜头景别/视角、眼部遮挡 | 视线动作 |
| 手部 | 姿势手部状态 | 手持道具 |
| 设备画质 | 拍摄设备 | 画质修饰 |
| 人设 | 情绪 | 眼神 |
| 昼夜 | 场景昼夜 | 光源 |
| 色彩 | 胶片色彩模式 | 色彩特效 |
| 妆容 | 基础妆容 | 糊妆效果 |

显式选择不具有越过这些关系的特权；它只绕过亲和采样。用户显式产生的硬冲突必须按表消解，并在 decision 中保留 `mode=explicit` 或 `mode=custom` 的来源证据。

同一冲突域内存在多个同级候选时，按原始全局 `tag_order`、`span_order` 升序保留首项。禁止使用 set 遍历、字典偶然顺序或随机选择决定胜者。

### 7.4 变更动作

- `drop`：只删除败者 Atom；decision 的 `after_text` 为 `null`。
- `replace`：旧 Atom 进入 tombstone，新 Atom 使用新 ID；新 Atom 的 parent 包含旧 Atom，且携带 resolver origin。
- `inject`：新 Atom 的 parents 必须是触发该注入的全部直接来源；例如纹身融合 Tag 关联到纹身选择器/叶子。
- 一个 decision 只描述一个目标 Atom 的一次动作。批量删除必须产生多条 decision。
- `rules_applied` 是按 DAG 实际首次产生 decision 的规则 ID 去重序列；仅检测无变更不能进入该数组。

### 7.5 最终不变量与异常

全部规则执行后，再运行无副作用的 `detect_hard_conflicts()`：

- 它使用与规则同源的语义约束和 fallback 编译对象，但不得修改 Atom、消费 RNG 或产生 decision。
- 可检测范围内若仍有硬冲突，写入 `unresolved_conflicts`。
- 如果冲突败者可删除/可替换却残留，视为实现错误并抛 `UnresolvedConflictError`。
- 如果唯一败者是不可删除的受保护复合结构，也抛同一异常，并标记原因 `protected_syntax_conflict`；不得静默保留。
- 纯 ANGLE/QUOTED 黑盒内容保持完全不透明，不做语义声明，也不因内部字节触发错误。

幂等契约：将首次输出 Atom 与同一 effective seed 再传入 resolver，输出 Atom 序列、文本和哈希必须完全相同，第二次 `decisions=()`、`rules_applied=()`、`unresolved_conflicts=()`。

- 对每个情境/槽位固定执行 `N=20,000` 次纯 sampler 抽样，以理论 `P_s` 为期望，要求总变差距离：

```text
TVD = 0.5 × Σ_i |observed_i - expected_i| <= 0.03
```

统计测试使用固定 seed 集且不依赖墙钟；失败输出情境、槽位、候选、期望/实测概率和 TVD。

### 11.5 10,000 组全链随机

使用 seeds `0..9999`，普通生成器全部可采样槽位设为 Random/Auto，确保可选槽位也实际进入随机路径。每组断言：

- 相同 seed 两次输出和审计 JSON 完全相同。
- `unresolved_conflicts` 为空。
- parent/origin 闭环。
- 输出可重新解析，受保护结构完整，字数不超过既有边界。
- 对首次 accepted atoms 二次消解零新增 decision。

77 个预设、8 个配方及其组合另做逐项全链测试，不用它们替代上述 10,000 组。

### 11.6 纯文本质量基准

建立冻结夹具，至少包含 14 个情境各一组正常组合和一组高冲突组合，共不少于 28 组；每组声明输入 Atom、预期硬冲突、非冲突显式 Tag 和允许动作。先从 `fe88185` 生成 rc7 快照并记录基线 SHA，再运行 rc8。

指标定义：

| 指标 | 计算方式 | 门槛 |
| --- | --- | ---: |
| 残余硬冲突率 | 有至少一个可检测硬冲突的输出数 / 总输出数 | `0` |
| 非冲突显式标签保持率 | 输出仍可追溯到的非冲突显式标签数 / 输入该类标签数 | `100%` |
| 规则误删率 | 无 oracle 冲突依据的 drop 数 / 全部 drop 数；无 drop 时为 0 | `0` |
| 来源与决策闭环率 | parent 可闭环且动作字段完整的 Atom/decision 数 / 总数 | `100%` |
| 正常组合有效 Tag 保留率 | accepted 有效 Tag / 输入有效 Tag，按夹具宏平均 | 不低于 rc7 |
| 高冲突平均删除量 | 每组 drop Atom 数的算术平均 | 不高于 rc7；增加项逐条提供新增硬冲突证据时例外 |

高冲突“新增证据”必须指向稳定 reason code、语义事实与具体输入/输出 Atom，不能用主观画面偏好解释。
