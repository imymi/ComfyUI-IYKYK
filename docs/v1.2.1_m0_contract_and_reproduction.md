### 2. 随机补全触发与边界判定表

> 范围界定：需区分“自动补全”和“已有完整穿搭的保护”：
> - **自动补全**：仅约束未豁免的系统随机服装生成路径（`服装款式 = 随机/自动` 且无外部服装覆盖，且目标等级需要完整/主要穿搭）；`服装款式 = 无`、`显式单品` 与 `外部服装覆盖` 均豁免“缺另一半衣物”的自动补全与缺件报错。
> - **已有完整穿搭的保护**：对于未豁免的随机穿搭以及**显式选择的完整套装/组合**（例如 `REP-BUDGET-03` 中显式选择的 `啦啦队服 (Cheerleader)`），在消解与词数预算裁剪阶段仍须防止被拆散为缺件输出；`服装款式 = 无` 与 `显式单品` 的豁免继续保留。

| 条件组合 | 是否自动补全穿搭 | 规则说明 |
|---|---|---|
| `服装款式 = 随机 / 自动` 且无外部服装覆盖，目标等级需要主要穿搭（L1 / L2，或 L3/L4 特定分支需要保留的构件） | **是** | 主款先抽（保留其风格/场景亲和与来源链） → 判定缺件 → 使用**独立随机子流**从受等级/载体/场景约束的候选池补件（每件保留各自目录 `item_id`、事实与 `SelectionOrigin`） → 若无相容补件，使用经校验的该等级最小组合回退并记录原因 |
| `服装款式 = 显式单品`（例如显式指定 `hoodie` 或 `miniskirt`） | **否（豁免完整检查）** | **不自动追加另一套衣服**，亦**不因只指定单件上装/下装而报错**；显式单品仅受目标等级兼容性和物理约束检查，只有当单品或显式状态自身与目标等级/物理约束硬冲突且无法保留有效选择时才报告冲突 |
| `服装款式 = 无 (None)` | **否（豁免完整检查）** | `None` 表示**跳过服装槽位**（输出不含系统服装词），不是“强制裸体”；**允许 `L1 + 服装=None` 兼容通过**，不自动追加衣服，也不报缺件冲突 |
| 存在外部服装覆盖（`clothing_override` / `服装_override` 等） | **否（豁免自动补全）** | 遵守 1.2.0 外部优先契约，**不自动追加另一套衣服**；若外部服装导致内部等级让位，诊断必须明确说明 |
| `服装状态 = 无 (None)` 且 `服装款式 = 随机 / 自动` | **基础补全执行，状态/扩展不加** | 不生成状态词和扩展词（`state_tags=()`、`extension_tags=()`），但 L1/L2 等级要求的基础完整穿搭补全仍执行 |
| 冲突消解或规则改写后 | **改写事实对齐 + 至多受控重组 1 次** | 任何规则改写（如材质替换）产生的新原子必须保持文本与语义事实一致，并重新接受目标等级校验；若是未豁免的系统随机穿搭在消解后缺件，最多受控重组 1 次并重走完整消解，仍不满足则明确报错（禁止无限重抽或悄悄返回缺件结果） |

### 3. 裸露等级 L1–L6 目标状态与相容分支判定表

> 核心原则：**等级是目标状态，不是单纯上限。** 每次仅选定 **1 个相容状态分支**，在同一分支内约束 `nudity` 提示词、基础服装、穿脱状态、扩展词及其他槽位语义，禁止跨分支混拼。

| 等级 | 目标视觉状态 | 允许状态分支（单次择一） | 穿搭补全与保留要求 | 扩展词策略（`clothing_extension`） | 跨槽位约束（非服装槽位） |
|---|---|---|---|---|---|
| **L1** 包裹暗示 | 全身主要区域完整着装（`upper_torso + lower_torso` 覆盖）；允许修身勾勒，**零裸露状态混入** | `l1_full_clothed` | **强制完整穿搭**（`top+bottom` 或有效 `one_piece` / `ensemble`）；拒绝纯内衣、比基尼、透视、仅鞋袜/外套独立输出 | **0 条**（绝对禁用） | 排除偷窥/窥底视角 (`between_legs_angle`)、成人情趣道具、情色光影、露骨/成人主题（`theme`）、露乳/下胸纹身、乳环/裸胸身体链、遮胸裸体发型、露肉动作 |
| **L2** 差分微露 | **主要穿搭保持完整**，在此基础上允许 1 处符合分支的局部微露；禁止因缺件变成半裸 | 1) `l2_collar_neckline`（领口/微解扣微露锁骨/上胸）<br>2) `l2_shoulder_strap`（单肩/吊带滑落）<br>3) `l2_midriff_waist`（分体露腰）<br>4) `l2_leg_slit`（裙摆高开叉/露踝）<br>5) `l2_backless`（露背款/露背设计）<br>6) `l2_sheer_hint`（适配轻薄面料的微透轮廓） | **强制保持完整主要穿搭**（缺上/下/内搭时补全）；仅允许与所选分支物理兼容的主款/状态（如厚重毛衣/羽绒服/铠甲禁止 `l2_sheer_hint`；无纽扣圆领禁止 `l2_collar_neckline` 解扣词；分体露腰禁止与 `backless dress` 混拼） | 允许 `L2` 级兼容扩展（须与材质及载体拓扑一致） | 禁止直接暴露乳房/乳头/私处词；禁止窥私处特写视角；禁止与 L1 一样的显式性行为/露点词 |

> **不误判保护（Non-False-Positive Rules）**：
> - 负向提示词（`negative`）中的裸露词绝不计入正向提示词越界；
> - 正常非人体裸露英语词汇（如妆容中的 `sheer nude lip gloss`、`nude peach satin lips`，场景中的 `bare bulb`、`bare trees`、`bare walls`，配方中的 `bare face`）在语义判定时必须依据槽位与结构化事实豁免，不误判为 L5/L6 裸露越界；
> - 黑盒受保护语法（`<lora:...>`、`"..."`、权重 `(text:1.2)`、调度 `[a:b:10]`）遵守现有保护契约，自由文本不承诺自动理解补全。

### 4. 入口优先级、外部覆盖与最终输出流水线契约

1. **四节点接口兼容不变**：
   - `IYKYKPromptGenerator`、`IYKYKPresetBrowser`、`IYKYKCustomSlotCombiner`、`IYKYKPromptDiagnostics` 的节点名、端口名、端口类型、默认值、输出数量和输出顺序保持不变。
   - `IYKYKPresetBrowser` 与 `IYKYKCustomSlotCombiner` 不新增必填端口，也不暗中注入默认 `L1`。
2. **生成器与预设/配方联动优先级**：
   - `IYKYKPromptGenerator` 显式选择 `L1`–`L6` 且启用 `预设模板`（固定或随机）和/或 `风格配方` 时：目标等级作为统一约束对象进入预设与配方装配链路，过滤/替换不兼容片段；若预设核心内容与目标等级不可调和且过滤后无合法保留主体，明确报错并输出诊断。
   - `IYKYKPromptGenerator` 选择 `裸露等级 = 随机 (Random)` 且启用 `预设模板` 时：沿用预设自身状态（不强制套用随机等级覆写预设原意，兼容既有 693 矩阵行为）。
   - 未启用预设时，即使界面 `裸露等级 = 随机 (Random)`，也会在采样最前端抽定唯一目标等级与状态分支，并贯穿全部槽位。
3. **外部覆盖优先与诊断说明**：
   - 保持 1.2.0 外部输入优先契约。当外部槽位输入（如 `clothing_override`、`nudity_override`、`pose_override` 等）与内部等级约束冲突时，外部输入胜出，内部等级约束让位并在 Diagnostics 2.0（`overrides` / `decisions` / `description`）明确说明“外部覆盖导致等级让位”。
   - 两个外部输入之间发生硬冲突时，仍 Fail-Closed 抛出 `PromptValidationError`。
4. **最终统一流水线顺序**：
   **确定等级与分支 → 采样与穿搭补全 → 应用外部覆盖 → 冲突消解 → 完整性检查（至多受控重组 1 次） → 去重与预算裁剪 → 最终语义校验**
   - **预算裁剪保护**：去重后进行词数预算控制时，优先保留外部覆盖内容与系统目标状态/完整穿搭所需的最小必需构件，优先裁剪可选修饰（`scene_detail`、可选质感、风格修饰等）；若外部或最小必需核心本身无法容纳于预算内则明确报错；保留 `max_words == 0` 返回空提示词的既有契约。
   - **最终校验**：针对最终输出（accepted atoms 与渲染文本）执行语义与完整度校验，不得只查采样中间结果（完整度校验按“随机补全触发与边界判定表”区分非豁免随机穿搭与 `服装=None`/显式单品/外部覆盖豁免入口；规则改写后的原子须保证文本与事实一致并复检目标等级）；中文诊断概要明确区分：`已补全`、`已调整`、`外部覆盖导致等级让位`、`无法生成`。
